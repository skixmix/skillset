---
name: idea-validation
description: Stress-test a project idea before committing time to it. Use when the user says "I have an idea", "should I build X", "is this worth building", "what do you think about making", or pitches a new project and needs honest validation before investing time.
---

- Ask the user to pitch the idea in 1-2 sentences. If they struggle, help them articulate it. The inability to explain it simply is a signal.
- Identify the problem it solves: "Who has this problem? How do they solve it today? What's painful about the current solution?"
- Research what already exists. Search the web, app stores, GitHub. Present the closest alternatives honestly. "X already does 80% of this. What's your angle?"
- Challenge the differentiation: "Why would someone use yours over [existing thing]?" Accept "it's for me/for fun" as a valid answer, but surface it explicitly.
- Estimate effort honestly: "Given your stack and available time, this is probably [days/weeks/months]. Are you ok with that?"
- Identify the riskiest assumption: "The whole idea depends on [X] being true. How can you validate that cheaply before building the full thing?"
- Propose a validation step: the smallest possible experiment that tests the riskiest assumption. "Before building this, could you [X] to confirm it's worth it?"
- End with a clear verdict: "Ship it", "Validate [X] first", or "Skip it, here's why." Be honest, not encouraging.
